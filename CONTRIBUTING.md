# Процесс разработки

## Жизненный цикл задачи

1. **Трекер — GitHub Issues + Projects.** Иерархия: эпик → задача → подзадача (sub-issues).
   Любая работа начинается с issue; без issue ветку и коммиты не создаём.
   Номер issue `N` — это и есть `SF-N`.
2. **Одна задача — одна ветка — один PR.** Ветка всегда от актуального `master`: `SF-N-slug`
   (латиница, нижний регистр, дефисы), например `SF-12-transcribe-whisper`.
3. **TDD строго: red → green → refactor.**
   - Сначала коммит с падающим тестом, затем коммит с реализацией, затем (при необходимости) рефакторинг.
   - Код без теста не принимается. Исключение — чисто документационные и конфигурационные изменения.
   - Тяжёлое (модели, GPU, ffmpeg на больших файлах) прячем за интерфейсами и мокаем;
     реальные прогоны помечаем `@pytest.mark.slow` / `gpu` — в CI они не запускаются.
4. **Коммиты:** одна строка, без тела и trailer-ов, без Conventional Commit-префиксов:
   `[SF-N] <одно предложение по-русски>`. Английский — только для имён переменных, функций,
   пакетов, переменных окружения. Один коммит — одно логическое изменение.
5. **Pull request** в `master`, шаблон заполняется полностью, в описании `Closes #N`.
   Слияние — только «Rebase and merge» (история остаётся по одному коммиту на изменение).
6. **Проверки (должны быть зелёными для слияния):**
   - `check` — `ruff check`, `ruff format --check`, `pytest` с покрытием не ниже 80%;
   - `conventions` — имя ветки и формат коммитов;
   - ревью агентом `reviewer` (`.claude/agents/reviewer.md`): все «must fix» закрыты.
7. **Прямые пуши в `master` запрещены**, `master` всегда зелёный.

## Локальная проверка

```powershell
pip install -e ".[dev]"
scripts\check.ps1      # Linux/macOS: scripts/check.sh
```

## Декомпозиция

- Эпик описывает цель; задача — то, что делается за один PR (ориентир — не более ~300 строк диффа).
- Если задача не помещается в один PR, она делится на подзадачи, у каждой своя ветка и PR.
- Решения «взять локальную модель или API» и подобные исследования оформляются как `spike`:
  результат — документ в `docs/decisions/` и вывод в issue.
