# shorts — правила для агента

Проект: автоматическая нарезка **длинных** видео на шортсы. Главный приоритет — качество выбора
законченных по смыслу моментов; формат 9:16 и допконтент — вторичны. Автопубликации в MVP нет.
Исходники в MVP лежат в локальной папке (позже — по ссылке). Запуск на ПК пользователя (Windows, GPU).
Секреты — только локально (`.env`, вне git). Язык общения и комментариев — русский.

Процесс (ветки, коммиты, TDD, PR) — см. [CONTRIBUTING.md](CONTRIBUTING.md). Это обязательно:

- Без issue работу не начинать. Одна задача = ветка `SF-N-slug` от master + один PR.
- Сначала падающий тест (отдельный коммит), потом реализация. Покрытие >= 80%.
- Коммит: `[SF-N] одно предложение по-русски`, без тела и trailer-ов.
- Перед завершением: `scripts/check.ps1` (или `check.sh`) зелёный; затем ревью агентом `reviewer`.
- Никогда не пушить в master напрямую.

## Архитектура (стиль wb-bank-integration, адаптация под Python)

Слои, зависимости направлены внутрь:

```
src/shorts/
  domain/          # типы, enum, ошибки; без I/O
  services/        # бизнес-логика пайплайна, оркестрация
  infrastructure/  # ffmpeg, whisper, llm, хранилище, файловая система
  cli/             # точки входа
```

- Зависимости сервисов — через конструкторы (DI); интерфейсы — `typing.Protocol` в `interfaces.py`
  рядом с сервисом, без префикса `I`. Конструкторы/фабрики — `build_*` или `__init__`.
- Паттерны: Repository для хранилища, Service для логики, Strategy там, где вариативность
  (LLM-провайдер: Ollama / Claude API; режимы рендера).
- Ошибки: именованные типы в `domain/errors.py`; на границах оборачивать с контекстом
  `raise StageError("transcribe.run: ...") from err`; ранний return вместо вложенных `if`.
- Этапы пайплайна идемпотентны и кешируют артефакты на диск: повторный запуск не пересчитывает готовое.
  Внешние/дорогие вызовы (LLM, ffmpeg) — отдельно от записи состояния; состояние пишется после
  подтверждённого успеха шага.
- Логи структурированные (поля `source_id`, `stage`, `clip_id`). **Не логировать полные транскрипты,
  промпты и ответы LLM на уровне INFO** — только DEBUG и только локально.
- Тесты: pytest, `parametrize` для табличных кейсов, фейки/моки на границах (`Protocol`-совместимые),
  маленькие синтетические видео для ffmpeg-тестов, никаких реальных моделей в обычных тестах.

## Стиль кода

- DRY, KISS, YAGNI. Функции <= 20–30 строк, одна ответственность, вложенность <= 3.
  Линтер ограничивает сложность (<= 8), число аргументов (<= 5) и statements (<= 25).
- Типы везде (`from __future__` не нужен на 3.13), `pathlib.Path` вместо строк-путей,
  `dataclass(frozen=True)`/pydantic для данных, неизменяемость по умолчанию.
- Импорты: stdlib → blank → third-party → blank → локальные (`ruff` сортирует).
- Docstring на русском для публичных функций/классов — что делает и какой поток.
- Безопасность: нет секретов в коде и логах; пути из конфига валидировать; `subprocess` —
  списком аргументов, без `shell=True`; ввод проверять на границе.

## Старый код

Прежняя версия лежит рядом, вне репозитория (`C:\Users\SS\shorts_factory`): переписываем с нуля,
берём только полезное (ffprobe/нормализация, сигналы сцен/аудио, рендер 9:16). Перенос — отдельными
задачами и с тестами, не копированием.
